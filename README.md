## Даалгавар 4: Newman ажиллуулалтын үр дүнгүүд

### Exit Codes
- **PASS exit code:** `0`
- **FAIL exit code:** `1`
- **DOWN exit code:** `1`

### Интерфейсийн ба Oracle-ийн алдааны ялгаа (DOWN тайлбар)
`ECONNREFUSED` алдаа нь сервер унтарсан үед сүлжээний/интерфейсийн түвшинд холболт тогтоож чадаагүйг харуулна. Энэ нь API-ийн логик эсвэл тест шалгуурын (oracle assertion) алдаа биш, харин дэд бүтэц ажиллахгүй байгааг илтгэх холболтын алдаа юм.

## Даалгавар 5: Нийтийн API (JSONPlaceholder)
JSONPlaceholder API нь зөвхөн GET хүсэлт ашигладаг, setup өгөгдөл шаардлагагүй тул шалгахад хялбар байсан. Харин бидний локал API нь PUT хүсэлтээр төлөв үүсгэж (stateful setup) байж POST шалгадаг тул тестүүдийн хоорондын бие даасан байдлыг хангах нь илүү төвөгтэй байв.

## Дүгнэлт
Энэхүү лабораторийн ажлаар REST API дээр систем тест хийх 5 алхамт процессыг бодитоор хэрэгжүүлж сурлаа. Тестийн дизайны 5 алхмаас хамгийн их бодол шаардсан нь Спецификаци хийх ба Давхар алдааны приоритет тогтоох алхам байв. Зааварт давхар алдааны үед аль алдаа ирэхийг заагаагүй байсан тул серверийн логикт кодчилсон дарааллыг тест хийх замаар тодорхойлсон. Тухайлбал, "Оюутан байхгүй" болон "Хичээл байхгүй" хоёр алдаа зэрэг үүсэхэд систем эхлээд оюутныг шалгаж ERROR_NO_STUDENT алдааг буцааж байгааг тогтоов. Боломжгүй хослолын хувьд JSON формат буруу үед өөр бусад функционал шалгалтууд хийгдэх боломжгүй байсан. Бидний бичсэн тестүүд сервер дээрх registrationID-ийн авто-инкремент утга болон алдааны кодуудыг үнэн зөв буцааж байгааг баталгаажуулсан. Мөн Newman хэрэгслийг CLI орчинд PIPE болон exit code-той ажиллуулж сурлаа. Түүнчлэн серверийн холболт тасарсан үеийн сүлжээний алдаа (ECONNREFUSED) болон логик тестийн фэйл хоёрын чанарын ялгааг ойлгож авсан. Эцэст нь, тест бүрийн өмнө PUT setup хийснээр тестүүдийг бие даасан, давтан ажиллуулахад найдвартай болгож чадлаа.
