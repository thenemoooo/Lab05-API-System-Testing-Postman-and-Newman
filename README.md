## Дүгнэлт
Энэхүү лабораторийн ажлаар REST API дээр систем тест хийх 5 алхамт процессыг бодитоор хэрэгжүүлж сурлаа. Тестийн дизайны 5 алхмаас хамгийн их бодол шаардсан нь Спецификаци хийх ба Давхар алдааны приоритет тогтоох алхам байв. Зааварт давхар алдааны үед аль алдаа ирэхийг заагаагүй байсан тул серверийн логикт кодчилсон дарааллыг тест хийх замаар тодорхойлсон. Тухайлбал, "Оюутан байхгүй" болон "Хичээл байхгүй" хоёр алдаа зэрэг үүсэхэд систем эхлээд оюутныг шалгаж ERROR_NO_STUDENT алдааг буцааж байгааг тогтоов. Боломжгүй хослолын хувьд JSON формат буруу үед өөр бусад функционал шалгалтууд хийгдэх боломжгүй байсан. Бидний бичсэн тестүүд сервер дээрх registrationID-ийн авто-инкремент утга болон алдааны кодуудыг үнэн зөв буцааж байгааг баталгаажуулсан. Мөн Newman хэрэгслийг CLI орчинд PIPE болон exit code-той ажиллуулж сурлаа. Түүнчлэн серверийн холболт тасарсан үеийн сүлжээний алдаа (ECONNREFUSED) болон логик тестийн фэйл хоёрын чанарын ялгааг ойлгож авсан. Эцэст нь, тест бүрийн өмнө PUT setup хийснээр тестүүдийг бие даасан, давтан ажиллуулахад найдвартай болгож чадлаа.

## Нэмэлт даалгавар: AI туслахаар хийлгэсэн тест ба харьцуулалт

### 1. Туршилтын гүйцэтгэл ба баталгаажуулалт
AI туслахаар шинжлүүлж гаргасан эквивалент ангиуд болон "ERROR_BAD_JSON" хязгаарын тохиолдлыг `lab05-collection-ai.json` файл болгон экспортлож, Newman-аар ажиллуулан үр дүнг баталгаажуулсан.
- **Тусгай цуглуулга:** `lab05-collection-ai.json`
- **Туршилтын үр дүнгийн файл:** `results/newman-ai.txt` (Assertions Executed: 2, Failed: 0)

### 2. AI ба Гар аргаар хийсэн дизайны харьцуулсан дүгнэлт
`server.js` кодод AI туслахаар шинжилгээ хийлгэж, Лекц 5-ын дагуу тестүүд үүсгүүлэн өөрийн гараар хийсэн дизайнтай харьцууллаа. 
(1) **AI-ийн орхигдуулсан зүйлс:** AI нь үндсэн логикуудыг зөв ангилсан боловч "Оюутан ч байхгүй, хичээл ч байхгүй" үеийн давхар алдааны приоритет (аль алдаа нь түрүүлж буцах дараалал) болон урьдач нөхцөлгүй хичээлийн (`prerequisites: []`) хязгаарын тохиолдлыг бие даасан тест болгож чадалгүй мартсан. 
(2) **AI-ийн олж харсан зүйлс:** Миний хийсэн дизайнаас гадна AI нь буруу JSON форматтай хүсэлтийн (`ERROR_BAD_JSON`) хязгаарын тохиолдлыг онцолж олсныг би өөрийн AI цуглуулгад нэмж туршсан. 
(3) **Oracle-ийн зөв эсэх:** AI-ийн санал болгосон oracle-ууд нь олон нөхцөлтэй `if-else` блок ашигласан нь тодорхой бус байдал үүсгэх эрсдэлтэй байсан бөгөөд зарим тохиолдолд `registrationID`-ийн утгыг хатуу шалгах хандлага ажиглагдсан. 
Дүгнэж хэлэхэд AI нь тестийн анхны санаа болон каркас үүсгэхэд маш хурдан бөгөөд ашигтай ч давхар алдааны логик дараалал, бие даасан байдал (Test Independence)-ыг тохируулахад инженерийн нарийн хяналт заавал шаардлагатай.
